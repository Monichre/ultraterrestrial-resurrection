# Playlist Ingestion Recovery

## Objective

Take the American Alchemy playlist (104 episodes, currently **0 retrievable rows**) to a verified corpus in the knowledge base. Four defects survive in the current ingestion path; this plan closes them and re-runs in stages that each prove themselves before the next begins.

**Done means:** `SELECT count(*) FROM document_chunks` returns a non-zero count for every episode whose state says `ingested`, confirmed by query against the database the app actually reads. The state field is not evidence — it has already reported success on a run that produced nothing.

**Scope:** the Python ingestion path under `apps/disclosure-rag`. **Non-goals:** the Next.js AI routes, connecting Python ingest to the app, new playlist sources, and re-architecting the prompt registry.

<Callout id="already-landed" tone="success">

**Most of the transcript-layer hardening already shipped.** The pipeline today already distinguishes a fetch failure from missing captions (`fetch_transcript` returns `(result, reason)`), maps private/age-restricted videos to a terminal `unavailable`, aborts the run after 3 consecutive IP blocks, clears stale per-episode fields on retry, and repairs malformed JSON once before giving up. This plan does **not** rebuild any of that — it closes what those changes left open.

</Callout>

### Step 0 — Point the pipeline at the database the app reads

Before any code changes, resolve where ingestion writes. `lib/db/postgres_client.py` reads `DATABASE_URL` from `apps/disclosure-rag/.env`, which resolves to `postgresql://liamellis@localhost:5432/ultraterrestrial` — a local database holding **0 documents and 0 chunks**. The shared Neon `neondb` that the app reads holds 189 documents and 4,946 chunks. The client's own docstring claims it points at the shared endpoint; in practice the local `.env` overrides it.

A successful re-run against the current config would produce rows nobody can retrieve. Settle this first, then confirm `OUTPUT_DIR` — the code writes to `BASE_DIR/data/playlist_ingestion`, but the artifacts now live in `corpus/intake/playlist_ingestion` after an untracked move, so a re-run today writes somewhere other than where the evidence sits.

### Step 1 — An ungraded pipeline is not an ingestion

`enrichment_outcome()` returns `"unknown"` when no `rag_pipeline.status` is found in any of the three containers it searches. The caller logs a warning that explicitly says it is "not treating as enriched" — and then records `status="ingested"` anyway. That single gap is what recorded `K4gYHs84BIc` as ingested while its own artifact on disk carried `"status": "error"` with zero chunks.

### Step 3 — Stop the parser from swallowing trailing output

`_extract_json_payload` falls back to a slice from the first `{` to the **last** `}` in the whole response. When a model emits a second object or trailing prose containing braces, that slice spans both, and `json.loads` reports `Extra data` — 6 episodes died exactly this way. `json.JSONDecoder().raw_decode` stops cleanly at the end of the first complete value and ignores everything after it, which removes the failure mode rather than repairing it after the fact.

<Diff
  id="rawdecode-diff"
  filename="apps/disclosure-rag/processing/rag_prompt_pipeline.py"
  language="python"
  mode="split"
  before={"    try:\n        return json.loads(stripped)\n    except json.JSONDecodeError:\n        start = stripped.find(\"{\")\n        end = stripped.rfind(\"}\")\n        if start >= 0 and end > start:\n            return json.loads(stripped[start: end + 1])\n        start = stripped.find(\"[\")\n        end = stripped.rfind(\"]\")\n        if start >= 0 and end > start:\n            return json.loads(stripped[start: end + 1])\n        raise\n"}
  after={"    try:\n        return json.loads(stripped)\n    except json.JSONDecodeError:\n        # raw_decode stops at the end of the first complete value, so a second\n        # object or trailing prose no longer widens the slice into `Extra data`.\n        decoder = json.JSONDecoder()\n        for opener in (\"{\", \"[\"):\n            start = stripped.find(opener)\n            if start < 0:\n                continue\n            try:\n                value, _end = decoder.raw_decode(stripped[start:])\n                return value\n            except json.JSONDecodeError:\n                continue\n        raise\n"}

### Step 4 — Constrain the two prompts that actually failed

`SCHEMA_ENABLED_PROMPTS = {"rag_ingestion"}` — one of five. The stage evidence says exactly which others need it: `disclosure.content_analysis` lost 31 of 47, and `rag_ingestion` lost all 16 that reached it. `document_classification` went 47-for-47 unconstrained and needs nothing.

Add `disclosure.content_analysis` to the set and confirm its registry schema is complete enough to constrain against — the file's own comment notes that schema-completeness for the unconstrained prompts was never verified, which is why they were left out. Leave `disclosure.ner` and `validation` alone until they demonstrate a failure; widening blindly trades one unverified assumption for another.

<Callout id="raw-persist" tone="risk">

**Persist raw model output on parse failure.** `_raw_text` is `.pop()`-ed from every stage result, so all 35 JSON failures can only be inferred from error strings — nobody can see the bytes that broke. Write the raw response into the `*_rag_pipeline.json` artifact on the failure path only. Without this, a second failed run is exactly as undiagnosable as the first.

</Callout>

### Verification

Green tests do not close this. The end-to-end check is a query against the database chosen in Step 0:

<Code
  id="verify-sql"
  filename="verify.sql"
  language="sql"
  caption="Run against the database the app reads. Any episode marked ingested with 0 chunks is a Step 1 regression."
  code={"SELECT d.id,\n       d.title,\n       count(c.id) AS chunks\n  FROM documents d\n  LEFT JOIN document_chunks c ON c.document_id = d.id\n WHERE d.id = ANY($1)\n GROUP BY d.id, d.title\n HAVING count(c.id) = 0;\n"}
/>

Pair it with a read of one `*_rag_pipeline.json` artifact confirming `status: "ok"` and a non-empty `embeddable_texts`, and a walk of the run report to confirm counts reconcile with `state.json`. Both records disagreeing is the condition Step 1 exists to catch.
