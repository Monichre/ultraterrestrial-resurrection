Platform Selection — Filling the Three Boxes

Architecture is decided (Option A: Library → own pipeline → single Postgres+pgvector). Now pick the vendor stack that fills: Box 1 = Object store, Box 2 = Postgres+pgvector, Box 3 = Compute for the ingestion workers.

Recommendation Supabase — one platform fills all three boxes natively. A xata-to-supabase.md migration plan already exists in this repo, and Supabase Storage handles the evidence file library without a separate vendor.

A · Supabase

all-in-one · Storage + Postgres + Edge Functions
  • Supabase Storage → S3-compatible bucket for PDFs, images, transcripts
  • Postgres + pgvector extension enabled by default, no extra wiring
  • Edge Functions + pg_cron + pg_net + Queues → "file lands → chunk → embed → index" loop native
  • RLS + auth available (Clerk still handles frontend auth)
  • xata-to-supabase.md migration plan already in this repo
Best fit for solo/small team: one dashboard, one bill, one mental model.
Watch-out: Edge Function execution limits for heavy embed jobs — mitigate with queue batching.

B · Neon + Vercel Blob

Vercel-native · serverless economics · DB branching
  • Vercel Blob → private + public object storage, native Vercel DX
  • Neon serverless Postgres + pgvector; scales to zero; preview-branch per PR
  • Vercel Functions + Cron + Queues for ingestion workers
  • No built-in auth — fine, Clerk already in use
  • Cleanest deploy DX since app already ships to Vercel
Watch-out: 3 separate products to wire and monitor; slightly more cognitive overhead than an all-in-one.

C · Self-host

Railway / Fly / VM · maximum control
  • MinIO, Cloudflare R2, or S3 — you choose and wire the object store
  • Local utr-pg pgvector container already half-set-up for dev
  • Embedding worker on Railway / Fly / any VM — you control scaling
  • No vendor lock-in; cheapest at scale
Watch-out: you own backups, uptime, failover, and all glue code. Heaviest ops burden for a research project.
Which platform fills the three boxes?
A

Supabase Recommended

One platform: Storage (evidence library) + Postgres+pgvector (relational + vectors) + Edge Functions/Queues (ingestion workers). Migration plan already exists. Fewest moving parts.

B

Neon + Vercel Blob

Best Vercel-native DX: serverless Postgres with DB branching + Vercel Blob object storage + Vercel Functions for workers. Three products but tightest deploy integration.

C

Self-host (pgvector + Railway/Fly)

Maximum control and lowest long-run cost. Local pgvector container half-done. Trade-off: you own ops, backups, and scaling for every layer.

Recommendation rationale: Supabase fills all three boxes with zero additional vendors, its Storage layer is built for large binary files (PDFs, image sets, video transcripts), and a migration playbook from Xata already exists in this repo — reducing the time-to-live considerably.
