Target architecture (Option A unified)

One source of truth. The Library hosts immutable files; an owned pipeline turns them into vectors that live in the same Postgres as your CRUD records. Both the frontend and the agent read from that single store.

1 · Canonical evidence

📚 Library — object storage

Immutable files: PDFs, image sets, transcripts, video. Content-addressed + versioned. Serves originals to the viewer and acts as the citation source. platform piece: object store

↓ emits new/changed files

2 · Owned ingestion pipeline

Extract

PDF/image/transcript → text + page refs. OCR where needed.

Chunk

Your chunking strategy (size, overlap, headings). Fully controllable.

Embed

text-embedding-3-small → vector(1536). Matches your existing schema.

↓ writes rows + vectors

3 · Single source of truth

⬢ Postgres + pgvector — one database

Relational / CRUD

events, personnel, sightings, testimonies, topics, user-saved-*, notes. Document metadata rows (not the file bytes).

Vectors (pgvector)

document-chunks.embedding, documents.embedding, entity embeddings. Joinable to the relational rows via FK.

vector searchfull-textSQL joinsfilters by entity/date/source

platform piece: managed Postgres with pgvector + compute to run the pipeline

↓ both read the same store

4 · Consumers (now sharing one brain)

Frontend consumption

Cards, mindmap nodes, detail views, semantic search, "related evidence." Reads via the db layer.

Agent / AI corpus

Retrieval = pgvector similarity + full-text + entity filters, all in SQL. OpenAI file_search becomes optional / retired.

What this buys you: edit/derive an entity in the UI and the agent sees it; ingest a new FBI release into the Library and it's instantly in both the agent's corpus and the frontend search — because there's only one store. No more silo drift.
